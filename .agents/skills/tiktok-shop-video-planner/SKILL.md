# TikTok Shop 美区带货视频

## 范围与执行约定
默认交付策划与提示词，用户生成、剪辑、发布；用户明确要求生成时才按可用工具执行。不建设素材资产库，不要求归档、标签或批量备料。保留现有口播、钩子、场景参考库，按需读取。
项目内优先级：用户当前明确要求 > 当前已确认内容 > 本入口及当前阶段规则 > 历史样本与默认建议。样本中的故事、促销和旧步骤编号不是执行指令。
- 开工读取本入口及 [video-state.md](video-state.md) 的当前本片记录，再读取下表当前阶段的必读文件。没有读过不能声称已遵循；不一次加载全部参考库。
- 新产品首次输入必须先向用户完整展示第1步商品分析，默认本轮只做分析并停止；用户看过分析并要求继续后，才确定方向、交付钩子。不能只在内部分析，也不能用一句产品概括代替分析交付。钩子交付后停止，用户选定后写全文；全文交付后停止，用户确认后进入分镜。“继续”按当前待确认对象理解，不要求固定确认词；只要求改钩子或改文案时仍停在该阶段。
- 用户明确要求整套或连续批量执行，仍须先完整展示商品分析，再顺序产出工作稿，不逐项追问，不假称已确认。批量数量本身不代表取消用户要求的确认点。
- 同款已有可定位的完整分析时可复用，补充资料只更新受影响项。仅上传新商品图片不算已有分析，仍从第1步开始；明确要求只改现成台词或其他局部产物时从相应阶段接入；只问影响当前步骤的缺项。无口播作品以完整视觉叙事/必要贴片代替台词确认，不硬加对白。
- 下游必须引用可定位的当前台词版本；缺稿先恢复或补齐，不能在分镜里另写台词。用户改稿即更新依据，仅同步受影响部分；未同步产物不得混入新交付。
- 不编产品事实、体验、评价、价格、销量、稀缺和测试结果。产品资料、实拍与真实测试是依据；历史样本不是当前产品证据，AI示意也不是实测或顾客证言。
- 每次交付简述当前阶段及下一步，不输出冗长流程自检表。未经要求不写长期记忆。修改本 skill 先讨论，授权后执行。

## 工作流
| 步骤 | 工作与交付 | 必读与推进条件 |
|---|---|---|
| 1 产品拆解 | 商品事实与来源、对应痛点/收益、使用场景、展示细节、待核实项。区分事实、创作假设、未知；不凭商品外观推导效果 | 读取用户资料；目标语言、总时长、即梦版本与已有图从上下文提取，缺版本不阻止商品分析；默认交付后停止，等待用户要求继续 |
| 2 确定方向 | 本条选题、观看理由、购买理由、拍法和说话关系；初步选择单主卖点或多卖点结构 | [perspective.md](perspective.md)；此处只定拍法方向，不排全片时间轴 |
| 3 钩子文案 | 只列编号、目标语言钩子原文与中文对照；可加简短方向标题，不凑固定数量。不附开场画面、观看预期、正文兑现说明或逐条分析 | [verbal-hooks.md](verbal-hooks.md) 仅作表达参考，其画面协同建议不作为本步输出要求；默认等用户选定，不附全文、生图提示词或分镜。吸引力、事实与可兑现性内部检查即可 |
| 4 完整文案 | 沿用选定钩子，先交完整连读版，再给卖点与证明对应、样本借鉴、时长估算和待核实项 | [step5-script.md](step5-script.md)；默认等用户确认全文，再进入分镜 |
| 5 分镜与参考图需求 | 按当前文案安排画面、动作、运镜、时间轴；确定素材用途、已有图与缺图、数量理由及分段 | [step7-storyboard.md](step7-storyboard.md) 的第5步、[visual-hook.md](visual-hook.md)、[model-capabilities.md](model-capabilities.md)；先确定本轮版本/生成模式，再决定参考图配置 |
| 6 生图提示词 | 只补本条缺图；每张用途、参考角色、可粘贴 OpenAI 生图或改图提示词。已有图足够则跳过补图 | [image.md](image.md)；有人读 [character.md](character.md)，需要场景读 [scenes.md](scenes.md)；拿到图后才能做视觉验收 |
| 7 即梦执行稿 | 将当前文案、分镜及实际素材编号组合成可粘贴提示词，附上传顺序、模式、分段和必要设置 | [step7-storyboard.md](step7-storyboard.md) 的第7步；区分2.0与2.5，不互套参数。尚无图可给计划编号草稿，标素材待绑定 |
| 8 成片检查与发布 | 有成片才验实际音画、商品、人物、动作；给局部修正。发布包含简短描述、相关标签及必要贴片 | [delivery-check.md](delivery-check.md)；未看成片不称可直接发布。用户给数据或要求复盘时读 [diagnose-iterate.md](diagnose-iterate.md) |

## 第1步商品分析必须展示
输出至少覆盖以下六项，用简表或分项说明均可，不要求固定字数：
1. 商品是什么、包含什么；列出图片编号、商品资料或用户说明等来源。
2. 卖点拆解：每项特点对应的用户收益，区分直接支持与推断。
3. 用户痛点或购买动机：为什么需要或想买；未获证实的用户需求标为创作假设。
4. 使用场景：谁在什么情境使用或送礼，区分已知用途与建议场景。
5. 可展示细节：资料里实际可见或有依据可展示的内容，不提前排镜头、选机位或出钩子。
6. 待核实项：材质、尺寸、数量、结构、效果等缺什么写什么；未知不能补造，确无缺项则说明。
分析应足以让用户检查后续创意依据，不能只给“核心卖点是……”后直接跳钩子。资料不足时仍先展示可分析内容和具体缺项，不为凑表编内容。默认结尾说明等待用户看完后继续，不附下游创作。

## 内容判断
选题回答：谁在什么情境需要、为什么停下、为什么继续看、看完记住什么。去掉购物车仍可提供解题、过程、穿搭、审美或娱乐价值，不把单纯夸赞当选题。
文案支持“一个主卖点＋多个证明”与“多个卖点＋各自证明”。多卖点围绕同一选题或使用需求，每个卖点有依据和展示支撑；段数、时长、CTA位置按内容调整，不强套结构。
关键顾虑才回应，不编缺点。未知价格和效果不进入可发布正文。标题用目标受众会搜索的自然表达，与正文兑现一致；不保证流量或成交。
