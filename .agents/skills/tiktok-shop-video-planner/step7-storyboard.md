# 第5步分镜方案 / 第7步即梦执行稿
遵循 [SKILL.md](SKILL.md)。两阶段沿用同一份文案和分镜，不重复创作台词。

## 第5步：分镜与参考图需求
输入：可定位的当前完整文案及状态、开场、产品、拍法、目标总时长。默认全文未确认不进入；整套授权可用当前工作稿，不能称已确认。找不到全文先恢复或补齐，禁止在分镜中另写一版。
先读 model-capabilities.md，识别本轮即梦2.0或2.5、具体入口与生成模式（首帧、首尾帧、全能参考等须以实际入口支持为准）。不同版本和模式分开配置；关键能力未核验可交创意方案，不宣称已适配。

### 时间轴
- 按台词实际朗读节奏分配秒级区间；全片时长、每次生成时长与分段衔接分别说明。不能把整条时长直接作为单次生成能力。
- 每段写当前台词原文/对应句、画面、人物或产品动作、相机动作、必要环境声。动作与运镜分开，一时刻不堆多个复杂动作。
- 一镜到底不写切镜；时间戳表示连续动作递进。切镜明确空间交接。段数由内容决定，台词与同步动作不机械相加。
- 画面不能增加原文没有依据的效果或抹掉顾虑；不为适配镜头偷偷删改台词。时长冲突先减无关动作，确需改词则回到文案步骤，按现有授权处理。

### 参考图清单
先查用户本条已有图片，不建素材资产库。每张记录计划编号、已有文件/待生成、用途、参考哪些特征、对应片段及必要性。
数量取决于缺少的信息，不等于镜头数，也不按上限凑图。完整场景图能同时表达人物、产品、环境时无需拆成三张；只有细节不清或新增场景等确有需要才补图。不把建议图数写成官方最低数量。
生成模式决定图片承担首帧、尾帧或主体/场景/风格参考，角色不得混淆。涉及人物读 character.md，场景按需读 scenes.md。
输出：分镜方案、分段理由、参考图需求及能力核验状态。随后第6步按 image.md 补缺图；已有图足够可直接进入第7步。

## 第7步：即梦可粘贴执行稿
读取当前文案版本、分镜、实际参考图及 model-capabilities.md。此步组合执行，不重新设计另一套剧情。
输出顺序：
1. 本轮版本、入口、模式、每段时长、画幅和需在界面设置的项目；只列已核验支持的设置。
2. 上传顺序与引用映射：实际文件/用户图片 → 界面素材编号 → 用途。按入口支持的引用方式写；计划编号不是实际绑定，未上传时明确标注替换要求。
3. 每段完整可粘贴提示词：参考角色与保持项、全局场景、时间轴、逐句对白及说话人、声音和必要限制。说明可中文，对白用目标市场语言。
4. 检查文案版本、对白遗漏或改写、时长、图号是否存在、用途冲突、空间与身份、模型适配状态。没有生成结果只能检查设计。
默认9:16、无生成字幕及BGM，保留对白与必要环境声；用户另有要求优先。贴片留后期。缺实际图片可以交计划引用草稿，不称已视觉验收或已绑定。2.0和2.5都要时分别给适配稿；未核验版本明确待核验，不冒充通用可执行稿。

## 开场与一致性
仅开场确需移动时加运镜，静态不硬加。快速甩镜时第一帧已在甩镜、对白同时开始，落点人物已在动作中；不得另加空镜、静默预卷或起点停留。速度按本条意图，不把固定帧数套到所有开场。手势跟相关台词与反应发生，开场不堆手势。
人物、商品几何/数量/标签、空间及光向保持一致；新场景说明转场。负面词不能替代清楚动作与实际验收。复杂动作先简化，必要时拆段；延长及编辑能力未核验不承诺。
每次修改同步 video-state.md 受影响项，按 delivery-check.md 检查。
